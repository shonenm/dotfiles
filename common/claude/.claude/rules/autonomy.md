# Autonomy Boundaries

- 質問・相談だけでは実装を開始しない。実装が承認されたら、必要な編集・削除・テスト・build・既存lockfileからの依存同期・割当開発環境の復旧は追加確認なしで実行する。
- 再生成可能な開発用DBのreset/seed・migration再適用、service再起動/再作成、不要な一時ファイル削除は通常の復旧操作である。repoの運用規則に従って実際の対象と影響を確認し、短く報告して続行する。localhostや開発用らしい名前だけで所有・再生成可能性を判断しない。
- 本番、他者が利用中の共有resource、再生成できないデータ、無関係な未commit変更を破壊する場合は明示承認を得る。利用者が明示した除外とtoolの安全制御は維持する。
- 計画・Issue・引き継ぎへ通常復旧の追加承認条件を勝手に書かない。過去の停止記録を現在の指示より優先しない。
- git push はユーザーが明示的に要求しない限り実行しない
- 「実行します」と述べたら同じターンでツールを呼ぶ。終了前に残作業・必要な検証・約束した手順を照合し、実行可能なものが残っていれば終えない
- ブロックされた場合は、試した操作・観測した制約・必要な外部アクションを報告する。ブロックに依存しない作業は続ける
- 計画と進捗はセッション内に保持する。TODO.md 等の計画ファイルは明示依頼時か成果物として必要な場合のみ作る
- commit 時は task に属する path / hunk だけを stage する。`git add -A` や `git commit -a` を使わず、既存の無関係な変更を含めない
